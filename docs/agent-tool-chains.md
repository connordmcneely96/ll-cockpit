# NEXUS Agent Tool Chains — Zero Paid API Policy

> Architecture document. Last updated: May 6, 2026.
> Rule: No paid APIs. Every gap filled with in-house business logic, Cloudflare-native tools, free tiers, or self-hosted open-source.

## Agent Tool Chains (Zero Paid API Edition)

### NEXUS (Orchestrator)

**Tools:**
- Cloudflare Cron Trigger — 6:50am daily MAPS briefing assembly
- D1 read — pulls sprint state, open tasks, recent agent_perf
- Telegram Bot API (free) — all Connor approvals via inline buttons
- Internal HTTP fan-out — routes tasks to specialist agent Workers
- NEXUS Knowledge `search_knowledge` — checks build history before routing

**In-house logic:**
- Intent classifier built on Workers AI (Gemma or Llama) — classifies every prompt before routing
- MAPS briefing assembler — D1 query → formatted morning brief → Cockpit chat post
- Approval gate — stores pending approvals in D1 `pending_approvals` table, resolves on Telegram callback

**Autonomy:** 95%. Connor only taps approve/reject on Telegram.

### SCOUT (Lead Generation)

**Tools:**
- Apollo.io API (free tier — 50 credits/month, enough for Phase 1 cold outreach)
- SearXNG (self-hosted VPS) — enriches leads with recent company news
- Firecrawl (free tier) — scrapes prospect websites for pain signal detection
- VPS LinkedIn scraper (port 3004, new — same pattern as X scraper) — pulls public company/contact data
- OpenClaw API (in registry) — queues approved leads for outreach sequences
- D1 `leads` table — all lead state stored natively
- NEXUS Knowledge `search_knowledge` — "have we worked this niche before?"

**In-house logic:**
- Lead scorer — Workers AI scores each lead 0-100 against Connor's three advantages (Fitness+AI, CAD+AI, Cloudflare+AI). Stored in D1.
- Deduplication — D1 query before any Apollo call to prevent re-processing known leads
- Enrichment pipeline — SearXNG company news + Firecrawl website scrape → consolidated lead brief

**Autonomy:** Apollo search nightly via Cron Trigger → score → queue top 10 for OpenClaw → Connor gets Telegram summary. No manual touch.

### INTAKE (Project Qualification + Onboarding)

**Tools:**
- Gmail MCP — reads replied prospect emails, triggers qualification flow
- Google Calendar MCP — autonomous kickoff scheduling
- Notion MCP — creates project brief page in client database
- Stripe API (free, pay per transaction) — generates payment link for 50% deposit
- Google Drive MCP — creates client folder structure
- D1 `cockpit_projects` write — project record on proposal send

**In-house logic (replaces PandaDoc/Docusign):**
- Contract generator — Cloudflare Worker generates HTML contract from D1 project template + client data. Stored in R2. Sent as Drive link.
- DocuSeal (self-hosted on VPS, port 3005) — open-source e-signature. Client signs via link in email. Webhook fires to D1 on signature.
- Proposal builder — Workers AI generates scoped proposal from project brief template + ATLAS engineering data
- 50% upfront trigger — INTAKE calls Stripe API to create payment link. No dashboard visit needed.

**Autonomy:** Prospect replies → INTAKE qualifies → proposal built → contract generated → DocuSeal sends for signature → deposit link issued → kickoff booked. One Telegram tap for proposal approval.

### FORGE (Code Generation)

**Tools:**
- GitHub MCP — pushes generated code to feature branch
- NEXUS Knowledge `search_knowledge` — "how did we solve this before?"
- Cloudflare Workers AI — code embeddings to check similarity against past solutions in Vectorize
- D1 `tool_calls` — every generation logged with input/output

**In-house logic (replaces E2B sandbox):**
- Pattern validator — before generating new code, FORGE queries Vectorize for similar past implementations. Reuses proven patterns instead of generating from scratch.
- Static analysis pass — FORGE generates → runs basic syntax checks via Workers AI → self-corrects before pushing
- Test scaffold generator — FORGE auto-generates test cases alongside code, stored in D1 `training_data` for META-COGNITION
- GitHub Actions CI integration — FORGE monitors CI results via GitHub webhook → D1 `tool_calls` → re-generates if tests fail

**Autonomy:** FORGE generates → validates patterns → pushes to branch → monitors CI → self-corrects on failure → hands to BUILDER when CI green.

### BUILDER (Autonomous Deploy + Self-Heal)

**Tools:**
- Cloudflare Pages Deploy API (free) — autonomous deploy
- Cloudflare Browser Rendering (free, binding) — screenshots deployed page, detects visual errors
- GitHub MCP — creates PR, merges after SENTINEL approval
- Cloudflare Workers tail — streams live logs, detects runtime errors within 60s
- Sentry MCP (free tier) — post-deploy error tracking
- Playwright MCP (free, open-source) — UI test automation against preview URL

**In-house logic (replaces paid monitoring):**
- Self-heal loop — 3-retry pattern with vision-based error detection already designed. BUILDER screenshots → Workers AI vision → identifies error type → re-prompts FORGE with specific diagnosis.
- Deploy log parser — Cloudflare tail logs parsed for error patterns, stored in D1. No paid log service.
- Visual regression checker — Browser Rendering screenshots before/after deploy, Workers AI compares, flags regressions

**Autonomy:** Deploy → screenshot → Playwright tests → Workers tail check → Sentry confirms clean → PR created → SENTINEL reviews → merges. Escalates to Connor only on 3rd failed self-heal.

### ATLAS (Engineering RAG)

**Tools:**
- Cloudflare Vectorize (`ATLAS_RAG` index) — engineering specs stored as vectors
- Cloudflare Workers AI — embedding generation
- Firecrawl (free tier) — crawls and ingests new engineering docs and API standards on schedule
- NEXUS Knowledge `search_knowledge` — cross-references project knowledge before answering
- Cloudflare AutoRAG — automated doc ingestion pipeline (free, evaluate vs custom)

**In-house logic (replaces paid research tools):**
- Doc ingestion pipeline — Cron Worker crawls tracked engineering doc URLs weekly via Firecrawl, chunks, embeds, upserts to Vectorize. No paid service.
- Citation tracker — every ATLAS answer includes source URL from Vectorize metadata. Stored in D1 for audit trail.
- Spec update detector — Cron Worker checks tracked spec pages for changes via SearXNG. Alerts NEXUS when API 610-682 or SolidWorks release notes update.

**Autonomy:** Self-updating knowledge base. Connor reviews outputs (required per agent definition). No manual doc uploads.

### HERALD (Content Engine)

**Tools:**
- Canva MCP (free tier) — generates visual assets for posts
- Gmail MCP — sends newsletter to subscriber list stored in D1
- Google Drive MCP — stores content drafts
- D1 `content_queue` table — all pending content with scheduled publish time

**In-house logic (replaces Buffer/Taplio/Mailchimp):**
- Content scheduler — D1 `content_queue` table stores approved posts with `publish_at` timestamp. Cloudflare Cron Worker fires every 30 min, checks for due posts, publishes via LinkedIn API (free) and X API (free basic tier).
- LinkedIn publisher — direct LinkedIn API calls from Cron Worker. No third-party scheduler needed.
- Auto-trigger hooks — BUILDER deploy complete, ANCHOR payment received, sprint complete → Queue message → HERALD draft → D1 `content_queue` → Telegram approval tap → publishes
- Newsletter sender — subscriber emails stored in D1 `subscribers` table. Gmail MCP sends via batch. No Mailchimp.

**Autonomy:** Every build event auto-triggers a HERALD draft. Connor taps Approve on Telegram. Publishes at optimal time from D1 schedule.

### SENTINEL (Quality Assurance)

**Tools:**
- D1 `agent_perf` write — every score logged natively
- D1 `training_data` write — high-quality outputs flagged for fine-tuning
- Cloudflare Queues — failed outputs queued back to originating agent automatically
- NEXUS Knowledge `search_knowledge` — pulls past successful outputs as scoring reference

**In-house logic (replaces Helicone/LangSmith):**
- Observability dashboard — SENTINEL writes structured perf records to D1. Cockpit /pipeline page reads D1 and renders quality trends. No paid observability tool.
- Cost tracker — every agent_perf record includes input_tokens, output_tokens, cost_usd. ANCHOR aggregates weekly. Total visibility from D1.
- Quality trend detector — Cron Worker weekly (Sunday) aggregates agent_perf by agent + task_type, computes rolling avg. Triggers META-COGNITION rewrite if avg < 0.70.
- Adaptive rubric — SENTINEL's scoring weights stored in D1 `sentinel_config` table. META-COGNITION updates weights based on Connor's approval/rejection patterns.

**Autonomy:** Scores → logs → queues back automatically. META-COGNITION gets data-driven weekly report from D1. No manual review.

### ANCHOR (Revenue + Invoicing)

**Tools:**
- Stripe API (free, revenue cost only) — creates invoices, tracks payments, manages retainers
- D1 `revenue` table — every transaction logged natively
- Telegram Bot API — payment received notification to Connor
- Google Calendar MCP — retainer renewal reminders 30 days before expiry

**In-house logic (replaces QuickBooks/Maxio):**
- Revenue dashboard — ANCHOR writes all Stripe events to D1 `revenue` table. Cockpit /settings renders MRR, pipeline value, conversion rate from D1. No accounting software.
- MRR calculator — D1 query on active subscriptions. Computed nightly by Cron Worker.
- Dunning logic (failed payment recovery) — built directly in ANCHOR. Stripe webhook fires on payment failure → ANCHOR queues 3 retry emails via Gmail MCP at Day 1, Day 3, Day 7. No Maxio.
- Retainer auto-renewal — ANCHOR creates Calendar reminder 30 days before retainer end date. Drafts renewal proposal. Routes to Connor for approval.
- Milestone billing — DISPATCH completion event → Queue message → ANCHOR issues corresponding milestone invoice. No manual trigger.

**Autonomy:** Zero manual finance work. ANCHOR handles full revenue lifecycle from invoice to dunning to renewal.

**Autonomy:** Runs fully in background. 7am digest every day. GENESIS alerts surface automatically. Connor configures tracked sources once in Cockpit settings.

## New D1 Tables Needed

Four new tables to support in-house replacements:

```sql
-- Content scheduling queue (replaces Buffer)
CREATE TABLE IF NOT EXISTS content_queue (
  id TEXT PRIMARY KEY,
  agent TEXT NOT NULL,
  platform TEXT NOT NULL, -- 'linkedin' | 'x' | 'email'
  content TEXT NOT NULL,
  visual_url TEXT,
  publish_at INTEGER NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending', -- pending | published | failed
  created_at INTEGER NOT NULL
);

-- Newsletter subscriber list (replaces Mailchimp)
CREATE TABLE IF NOT EXISTS subscribers (
  id TEXT PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  name TEXT,
  status TEXT NOT NULL DEFAULT 'active', -- active | unsubscribed
  subscribed_at INTEGER NOT NULL
);

-- Revenue events (replaces QuickBooks)
CREATE TABLE IF NOT EXISTS revenue (
  id TEXT PRIMARY KEY,
  stripe_event_id TEXT UNIQUE,
  project_id TEXT,
  client_id TEXT,
  type TEXT NOT NULL, -- invoice | payment | refund | subscription
  amount_usd REAL NOT NULL,
  status TEXT NOT NULL,
  created_at INTEGER NOT NULL
);

-- Pending Connor approvals (centralizes Telegram approval gate)
CREATE TABLE IF NOT EXISTS pending_approvals (
  id TEXT PRIMARY KEY,
  agent TEXT NOT NULL,
  action_type TEXT NOT NULL,
  payload TEXT NOT NULL, -- JSON of what's being approved
  telegram_message_id TEXT,
  status TEXT NOT NULL DEFAULT 'pending', -- pending | approved | rejected
  created_at INTEGER NOT NULL,
  resolved_at INTEGER
);
```

3. **Week 3:** SCOUT Apollo loop + OpenClaw. Lead machine.

6. **Week 6:** ORACLE digest. Intelligence layer.
7. **Week 7:** INTAKE contract + DocuSeal. Full sales pipeline.
8. **Phase 2:** REEL, BUILDER self-heal, SENTINEL dashboard.
